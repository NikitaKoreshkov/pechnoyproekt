## Задача

Мастерская печей продаёт не «товар», а проект: комплекс собирается из типа, мощности,
кладки, материалов и объекта на фото. Обычный каталог с ценой и кнопкой «в корзину»
здесь врёт — цены нет, есть смета.

Поэтому сайт строился как три вещи в одном: витрина с конфигуратором, портфолио,
которое продаёт доверие, и back-office, где менеджер ведёт заявки, тексты и
наполнение девяти направлений без разработчика.

## Что это (и чего это не)

**Это e-commerce без корзины.** Оформление идёт через `/checkout/[projectId]` — по
результату конфигуратора, а не по списку SKU.

**Это не «лендинг с админкой»:** 26 страниц панели ведут каталог, секции и
подобласти, hero, шапку, подвал, преимущества, FAQ, отзывы, этапы работ, SEO-тексты
каталога, юридические тексты, метаданные сайта и заявки с форм.

**Демо без базы — честная витрина, а не сломанная.** `lib/prisma.ts` строит
`PrismaClient` безусловно, а запросы к CMS-блокам обёрнуты в `.catch(() => null)`.
Без `DATABASE_URL` страница отдаёт 200 на код-дефолтах, но каталог, отзывы,
калькулятор и тексты блоков пустые: на главной **1 423 символа текста против 5 406
на проде**, и 10 из 12 контентных API отвечают 500. Это измерено, а не ощущается.

## Что делает этот код необычным

- **Девять направлений — девять отдельных сид-скриптов.** У каждого свой файл
  наполнения (`package.json` → скрипты), поэтому контент можно пересобирать
  независимо: обновили «казан-барбекю» — не задели «русские печи».
- **Портфолио режется двумя независимыми осями.** `/portfolio/types/[slug]` и
  `/portfolio/kladka/[slug]` — это среди реализованных объектов, а не фильтры в
  памяти браузера, то есть каждый срез имеет свой URL и индексируется.
- **PDF генерируются тремя способами одновременно.** `pdfkit` для потоковых
  документов, `@react-pdf/renderer` для декларативной вёрстки, `puppeteer` — когда
  договор нужен ровно таким, как его видит менеджер в браузере.
- **Учётка администратора не сидится.** Скрипты `create-super-admin.ts` и
  обновления читают только `ADMIN_EMAIL` и `ADMIN_PASSWORD` и падают с внятным
  сообщением, если их нет. Ни адрес сервера, ни логин с паролем в репозитории не
  хранятся.
- **Деплой на VPS ничего не знает о сервере.** `deploy.sh` берёт адрес, путь и ключ
  из окружения: `SERVER_IP=... SERVER_DIR=/var/www/pechnoyproekt SSH_KEY=./deploy_key ./deploy.sh`.
- **Валидация на `zod 4` — и для форм, и для API.** Одна схема кормит и клиент, и
  серверный роут, поэтому «прошло валидацию в браузере, упало на сервере» здесь не
  сценарий.

## Запуск локально

```bash
npm install
cp .env.example .env      # DATABASE_URL, NEXTAUTH_SECRET, NEXTAUTH_URL
npm run db:push           # схема в PostgreSQL
npm run db:seed-full      # направления каталога + настройки блоков
npm run dev
```

`NEXTAUTH_SECRET` генерируется через `openssl rand -base64 32`.

Учётную запись администратора заводим из окружения, не из сида:

```bash
ADMIN_EMAIL=you@example.com ADMIN_PASSWORD='strong-password' npx tsx scripts/create-super-admin.ts
```

Чтобы демо было наполненным, нужно указать проекту `DATABASE_URL` на любой
PostgreSQL и прогнать `npm run db:push && npm run db:seed-full` против него.

## Деплой

**Vercel:** фреймворк определяется автоматически, `postinstall` вызывает
`prisma generate`. Нужны `DATABASE_URL`, `NEXTAUTH_SECRET`, `NEXTAUTH_URL` и
`NEXT_PUBLIC_SITE_URL`.

**VPS:** на сервере процесс висит под PM2 (`ecosystem.config.cjs`) за nginx,
установка окружения описана в `setup_server.sh`.

## Известные ограничения

- **Демо без базы отдаёт пустой каталог** — цифры выше. Это режим работы, а не
  поломка, но по ссылке сверху видно только каркас.
- **Запросы к CMS «глотают» ошибку через `.catch(() => null)`.** Благодаря этому
  страница живёт без базы; обратная сторона — реальная ошибка БД на проде молча
  выглядит как пустой блок, а не как алерт.
- **`PrismaClient` строится безусловно**, без lazy-проверки наличия `DATABASE_URL`.
- **Три способа генерации PDF — это три пути поддержки.** Один и тот же договор
  может собираться по-разному в зависимости от того, какой модуль его вызывает.
- **Тестов — три файла** на 76 API-роутов: покрытие выборочное, остальное
  проверяется руками на проде.
